## 1. KPIダッシュボード自動更新設計

### 1.1 一元監視対象メトリクス

| カテゴリ | メトリクス | データソース | 更新頻度 |
|---------|-----------|-------------|---------|
| Stripe課金 | MRR / 新規課金数 / チャーン数 / ARPU | Stripe Webhook (`invoice.paid`, `customer.subscription.*`) | リアルタイム |
| 無料トライアル | トライアル開始数 / 有料転換数 / 転換率 | Stripe Webhook (`customer.subscription.trial_will_end`, `invoice.paid`) | リアルタイム |
| アフィリエイト | クリック数 / CV数 / 成果報酬額 | `affiliates` モジュール + UTMトラッキング | 日次集計 |
| リファラル | 招待リンク生成数 / 登録数 / 転換率 | リファラルAPI（実装予定） | リアルタイム |
| SEO/SNS | LP訪問数 / 登録CVR / 流入チャネル別内訳 | GA4 + UTMパラメータ | 日次集計 |
| 法人パートナー | 提携数 / 一括登録ユーザー数 / 法人経由MRR | 管理画面 + Stripe metadata | 週次集計 |

### 1.3 実装方針

## 2. トラフィック急増時アラート閾値・エスカレーションフロー

### 2.1 アラート閾値定義

| レベル | 条件 | アクション |
|--------|------|-----------|
| **INFO** | リクエスト数が直近1時間平均の 1.5倍 | ログ記録のみ |
| **WARNING** | リクエスト数が直近1時間平均の 3倍 OR レスポンスタイム p95 > 2秒 | Ops担当に通知（Slack/Discord） |
| **CRITICAL** | リクエスト数が直近1時間平均の 5倍 OR エラー率 > 5% OR DB接続プール枯渇 | 全チーム即時通知 + エスカレーション |

### 2.2 エスカレーションフロー

```
[アラート検知]
    │
    ├─ INFO → ログ記録、翌日レビュー
    │
    ├─ WARNING (5分以内に対応開始)
    │   ├─ Ops: サーバーリソース確認、キャッシュ状態確認
    │   ├─ DevSecOps(獅白): レートリミット動的調整検討
    │   └─ 15分で解消しなければ → CRITICAL へ昇格
    │
    └─ CRITICAL (即時対応)
        ├─ Ops: docker-compose scale で worker 増設
        ├─ DevSecOps: WAFルール追加/IPブロック（攻撃の場合）
        ├─ Dev: 緊急ホットフィックス（アプリ起因の場合）
        └─ CEO: 30分以内にステータス報告
```

### 2.3 施策別トラフィック急増シナリオ

| 施策 | 想定ピーク | トリガー | 準備事項 |
|------|-----------|---------|---------|
| インフルエンサー招致 | 通常の5-10倍（1インフルエンサーあたり） | インフルエンサーが投稿した瞬間 | LP・登録APIのキャッシュウォーム、レートリミット緩和 |
| 法人パートナーシップ | 一括登録で瞬間100-500リクエスト | 法人向け一括インポートAPI実行 | バッチ処理化、非同期キュー検討 |
| コンテンツSEO | 徐々に増加（急増リスク低） | バズ記事がSNS拡散 | CDNキャッシュ確認 |
| リファラルプログラム | 通常の2-3倍 | キャンペーン開始時 | 招待リンクAPIのレートリミット設定 |
| 無料トライアル | 通常の3-5倍 | プロモーション告知時 | Stripe API Rate Limit確認（25req/s） |

## 3. 無料トライアル→有料転換率 週次自動レポート

### 3.1 レポート項目

```
=== poker_sns 週次トライアル転換レポート ===
期間: YYYY/MM/DD - YYYY/MM/DD

■ サマリー
  トライアル開始数:     XX 名
  トライアル継続中:     XX 名
  有料転換数:           XX 名
  転換率:               XX.X%（目標: 30%）
  解約数:               XX 名
  解約率:               XX.X%

■ コホート分析
  先週開始コホート転換率:   XX%
  先々週開始コホート転換率: XX%
  トレンド:                 ↑改善 / →横ばい / ↓悪化

■ 転換タイミング分析
  トライアル1-3日目で転換:  XX%
  トライアル4-5日目で転換:  XX%
  トライアル6-7日目で転換:  XX%
  → 最多転換日: X日目

■ チャネル別転換率
  Organic:      XX%
  Referral:     XX%
  Influencer:   XX%
  Corporate:    XX%

■ MRRインパクト
  今週新規MRR:  ¥XX,XXX
  累計MRR:      ¥XXX,XXX
  月100万円まで: ¥XXX,XXX（XX%）
```

### 3.2 レポート生成フロー

**Phase 1（即時）**: 手動集計 → スプレッドシートテンプレートで週次更新（毎週月曜AM集計）
**Phase 2**: Stripe APIからデータ取得するスクリプト作成を Dev に依頼

```
[想定スクリプト仕様]
- Stripe API: subscriptions.list(status=trialing) + subscriptions.list(status=active, created>=7d_ago)
- 出力: JSON → Markdown形式レポート
- 実行: cron (毎週月曜 9:00 JST) or 手動実行
- 通知: Slack/Discord #ops-reports チャンネルに自動投稿
```

**Phase 3**: 管理画面内レポートページ（`/admin/reports/trial-conversion`）

### 3.3 アクション閾値

| 転換率 | 判定 | アクション |
|--------|------|-----------|
| 30%以上 | 良好 | 現状維持、スケール検討 |
| 20-30% | 要注意 | トライアル中のナッジ通知追加検討、UIフロー見直し |
| 20%未満 | 要改善 | プレミアム価値訴求の再設計、トライアル期間延長検討、緊急ミーティング |

## 5. DevSecOps（獅白）との連動計画

| 項目 | Ops 担当 | DevSecOps 担当 | 連動ポイント |
|------|---------|---------------|------------|
| 負荷テスト | テストシナリオ定義、結果分析 | テスト実行環境構築、ツール選定 | テスト結果からアラート閾値を校正 |
| レートリミット | 通常運用時の閾値モニタリング | エンドポイント別リミット設定・実装 | WARNING時に動的調整を連携実施 |
| ログ基盤 | ダッシュボード設計、KPI抽出クエリ | ログ収集パイプライン、セキュアストレージ | 同一基盤からOps KPIとSec監査ログを分離表示 |
| 監視ダッシュボード | ビジネスKPI面の設計 | インフラ/セキュリティ面の設計 | 統合ダッシュボードで一画面管理 |
