## 1. 連載コンセプト

### 1.1 タイトル案

**メインタイトル**: 「AI×個人開発 — 1人で月100万を目指すリアルな話」

**サブタイトル候補**:
- 「AIを武器にWebサービスを作って稼ぐまでの全プロセス公開」
- 「個人開発者がAIで開発・運用・マーケを回す実践記録」

### 1.2 ターゲット読者

| セグメント | ペルソナ | 刺さるフック |
|-----------|---------|------------|
| 副業エンジニア | 本業+αで月10万稼ぎたい20-30代 | 「AIで1人でも回せる」リアリティ |
| AI活用に興味がある開発者 | AIツールを導入したいが何から始めるか分からない | 「実プロダクトでのAI活用事例」 |
| 個人開発者 | サービスを作ったがマネタイズに苦戦中 | 「収益化の3本柱を1人で実装した話」 |
| これから個人開発を始めたい人 | アイデアはあるが技術選定/運用が不安 | 「ゼロから稼ぐまでの具体ステップ」 |

### 1.3 差別化ポイント

- **CEOの実体験ベース** — 理論ではなく「実際にやってみた結果」を数字付きで公開
- **AI活用のリアル** — 成功だけでなく失敗・落とし穴も正直に共有
- **個人開発の全工程** — 企画→開発→運用→マネタイズを1人で回すノウハウ
- **poker_snsは「具体例」として自然に言及** — 宣伝ではなく体験の一部として導線を設計

### 1.4 マネタイズ連動

| チャネル | 施策 |
|---------|------|
| note記事内CTA | poker_sns登録リンク (UTM付き) |
| 有料マガジン化 | 連載10本目以降で有料化検討 (月額980円 or 単品300円) |
| poker_sns Premiumへの誘導 | 「実際に作ったサービスのPremium機能」として紹介 |

| コンサル/メンター | 連載後半で個別相談メニュー開設 |

**想定文字数**: 約4,500字
**構成テンプレート**: `docs/note-templates/article-structure-template.md` の6ブロック構造に準拠

#### 構成

```
■ Block 1: フック（400字）
- 「個人開発のWebサービスを週5時間で運用している」という結論から入る
- 「1人で全部やってたら破綻した」という共感ポイント
- この記事で公開する内容の概要

■ Block 2: 背景・前提（600字）
- CEOのスペック（開発経験、使用技術スタック）
- サービスの規模感（機能数、ユーザー数の目安）
- 「自動化する前は週20時間以上かかっていた」というBefore

■ Block 3: 本題 — 自動化した5つの領域（2,000字）
- CI/CD: GitHub Actionsで自動テスト・デプロイ → 手動デプロイ30分/回 → 0分
- AIコードレビュー: PR作成時にAIがレビュー → レビュー待ち時間の削減
- SNS自動投稿: 定時投稿の自動化 → 毎日の投稿作業15分 → 0分
- 監視・アラート: 異常検知の自動通知 → 「問題が起きたら気づく」体制
- 記事執筆補助: AI構成→ドラフト→人間リライト → 執筆時間60%削減
  各項目に「導入前→導入後」の具体数値と使用ツール名を記載

■ Block 4: 失敗・落とし穴（600字）
- 失敗1: AIに任せすぎてバグを本番に出した話 → 最終チェックは人間
- 失敗2: 自動化の構築に3週間かかり本末転倒だった領域 → ROI計算の重要性

■ Block 5: まとめ（400字）
- 要点3行まとめ
- 「明日からできること」: まずCI/CDから始めるのが最もROI高い
- 次回予告: AIで記事を量産して「初月で売上が立った」仕組みの全貌

■ Block 6: CTA（200字）
- 「この記事で紹介した自動化を実際に使っているサービスはこちら」
- poker_snsリンク (UTM: ?utm_source=note&utm_medium=article&utm_campaign=ai_indiehacker_001)
- noteフォローCTA
```

## 8. リスクと対策

| リスク | 影響度 | 対策 |
|--------|--------|------|
| 執筆が追いつかない（3日サイクル） | 高 | Phase A（5本分）を先行執筆してバッファ確保 |
| コード公開による脆弱性露出 | 高 | 獅白チーム事前レビュー必須、本番値は絶対に載せない |
| PVが伸びない | 中 | X連動投稿、ポーカーコミュニティへの展開、note内SEO |
| 内容が技術寄りすぎて初心者離れ | 中 | 各記事冒頭に「この記事で学べること」を明示、図解を多用 |
| 競合記事との差別化 | 中 | 「実際の収益数字を公開」で信頼性担保 |
