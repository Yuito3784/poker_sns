## 1. 動画公開前チェックリスト

各動画を公開する前に、以下の全項目を確認する。週5本ペースで手戻りを防止するため、制作完了直後に実施すること。

### 1.1 解像度・フォーマット

| # | チェック項目 | 基準値 | 確認方法 |
|---|------------|--------|---------|
| F-1 | 解像度 | 1080 x 1920 px (9:16) | ファイルプロパティ確認 |
| F-2 | フレームレート | 30fps | ffprobe / メディアプロパティ |
| F-3 | エンコーディング | H.264 映像 + AAC 音声 | ffprobe / MediaInfo |
| F-4 | 総尺 | 60秒 (±1秒許容) | 再生確認 |
| F-5 | ファイル命名規則 | `poker_sns_hand_review_{NNN}_{platform}.mp4` | 目視確認 |

| S-3 | 左右安全マージン | 左右各60px 以内にテキストなし | フレームキャプチャ目視 |

## 4. QAゲートプロセス

### 4.1 週5本ペースの制作フロー内QA位置

```
制作 → Design確認 → QA確認 → 承認 → 公開
       (D-2)       (D-1.5)   (D-1)   (D-0)
```

| ステップ | 担当 | 所要時間 | 内容 |
|---------|------|---------|------|
| 制作完了 | Ops/制作 | -- | 動画ファイル + 説明文 + サムネイル納品 |
| Design確認 | Design | 30分/本 | テンプレート準拠、カラー、フォント、レイアウト確認 |
| QA確認 | QA/QC | 20分/本 | 本チェックリスト全項目実施 |
| 承認 | Planning | 10分/本 | 最終承認、公開スケジュール反映 |
| 公開 | Ops | 5分/本 | YouTube/Instagram同時アップロード |

### 4.2 週次QAバッチ処理

週5本を個別確認すると非効率なため、以下のバッチ運用を推奨:

| パターン | 運用 |
|---------|------|
| 月曜 | 月〜水分 3本の制作完了 → Design確認 |
| 火曜 | 3本のQA確認 → 指摘事項フィードバック |
| 水曜 | 木〜金分 2本の制作完了 → Design確認、月〜水分修正反映 |
| 木曜 | 2本のQA確認 → 指摘事項フィードバック、月〜水分最終承認 |
| 金曜 | 木〜金分最終承認、翌週スケジュール確認 |

### 4.3 クリティカル項目（即FAIL）

以下の項目に1件でも不合格がある場合、即座にFAIL判定:

- **F-1**: 解像度が1080x1920でない
- **S-2**: CTA等の重要テキストが下端250px安全領域に被っている
- **C-1**: ゴールドカラーが#c9a84c以外（ブランド毀損）
- **U-3**: /lp リンク先が200以外のレスポンス
- **U-5**: アフィリエイトリンクが遷移不能
- **CN-1**: ポーカーハンド情報に重大な誤り
- **A-4**: 著作権フリー素材のライセンス未確認

## 5. 判定基準・エスカレーション

### 5.1 判定ランク

| 判定 | 条件 | アクション |
|------|------|----------|
| **PASS** | 全チェック項目が合格 | 公開承認へ進行 |
| **CONDITIONAL PASS** | 軽微指摘1-2件（CN-3誤字など） | 修正後、QA再確認なしで公開可。修正記録のみ |
| **FAIL** | クリティカル項目1件以上不合格、または軽微指摘3件以上 | 公開停止。修正後にQA再チェック実施 |

### 5.2 エスカレーション基準

| 状況 | エスカレーション先 |
|------|-----------------|
| 同一指摘が3本連続で発生 | Design + Planning（テンプレート or 制作プロセスの根本対策） |
| /lp リンク障害 | DevSecOps + Dev（インフラ・アプリ緊急対応） |
| アフィリエイトリンク遷移不能 | Ops + Planning（パートナー連絡） |
| 週5本中3本以上がFAIL | Planning（制作ペース・品質トレードオフ再検討） |
