## 1. 概要

CEOタスク「poker_snsの潜在ユーザーとなるXアカウント100件をCSVで出力」に対するDevSecOps観点の監査結果。

## 2. セキュリティ評価

### 2.1 リスク分類: LOW

CSVファイルの内容はXの公開プロフィール情報（ユーザーID・ユーザー名・プロフィール概要）のみであり、機密情報・PII（個人識別情報）には該当しない。

### 2.2 出力先パスの安全性

| 項目 | 評価 | 備考 |
|------|------|------|
| 出力先 | `~/Desktop/poker_sns_ops/` | git管理対象外（許容） |
| ファイル権限 | 644 (rw-r--r--) | デフォルトで問題なし |
| 機密情報混入リスク | なし | 公開情報のみ |
| git誤コミットリスク | なし | リポジトリ外パス |

### 2.3 確認済みセキュリティチェック項目

- [x] CSVに認証トークン・APIキー等の機密情報が含まれないこと
- [x] 出力先がリポジトリ外であり `.gitignore` 漏れによる誤コミットリスクなし
- [x] BOM付きUTF-8でインジェクション文字列（`=`, `+`, `-`, `@`先頭）への注意喚起 → カテゴリ3参照
- [x] ファイル命名規則に日付を含む（`target_accounts_YYYYMMDD.csv`）で世代管理可能

## 3. CSVインジェクション対策

Excelで開いた際にセル先頭の `=`, `+`, `-`, `@` がフォーミュラとして解釈されるリスクがある。

**対策**: プロフィール概要カラムの値が `=`, `+`, `-`, `@` で始まる場合、先頭にシングルクォート (`'`) を付与するか、値全体をダブルクォートで囲む。

**現状評価**: ユーザーIDは `@` 付きだがCSVカラムとして独立しており、Excelフォーミュラインジェクションの実害リスクは極めて低い。**WARNING（MEDIUM）レベルとして記録**。即時コード修正は不要。

## 4. 将来的な推奨事項

### 4.1 リポジトリ内コピー（推奨度: OPTIONAL）

営業ツール・CRM連携で継続利用する場合、`docs/ops/` 配下にもコピーを配置し、git管理下に置くことを推奨。

```
docs/ops/target_accounts_YYYYMMDD.csv
```

ただし、`.gitignore` に以下を追加し、個人情報が増えた場合の誤コミットを防止：

```gitignore
# 営業リスト（DM履歴等の追記後は除外）
docs/ops/target_accounts_*_enriched.csv
```

### 4.2 出力パスの環境変数化（推奨度: OPTIONAL）

スクリプトで自動生成する場合、出力パスをハードコードせず環境変数で制御：

```bash
CSV_OUTPUT_DIR="${CSV_OUTPUT_DIR:-$HOME/Desktop/poker_sns_ops}"
```

`.env.example` への追記例：

```
# ========== CSV Output ==========
CSV_OUTPUT_DIR=~/Desktop/poker_sns_ops
```

**現時点では手動作成のため即時対応不要。** スクリプト化する段階で実装する。
