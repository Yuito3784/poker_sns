# note記事 制作パイプライン運用ガイド

## 概要
poker_snsのノウハウ共有note連載を3日おきに安定投稿するための制作パイプラインと運用ルール。

---

## 1. 制作パイプライン スケジュールテンプレート

各記事は **D-3（公開3日前）** を起点に以下のフローで進行する。

| フェーズ | タイミング | 担当 | 作業内容 | 完了条件 |
|---------|-----------|------|---------|---------|
| **構成・執筆開始** | D-3 | CEO / Planning | テーマ確定、見出し構成作成、本文執筆開始 | 見出し構成がSlack/管理ボードに記載済み |
| **ドラフト完成** | D-1.5 | CEO / Planning | 本文執筆完了（3000〜5000字）、スクリーンショット・コード例の挿入 | ドラフト全文が共有ドキュメントに記載済み |
| **QAレビュー** | D-1.5 → D-1 | QA/QC（雪花） | 文字数確認、誤字脱字、リンク動作、画像内個人情報マスク、コード動作検証 | QAチェックリスト全項目PASS |
| **セキュリティレビュー** | D-1.5 → D-1 | DevSecOps（獅白） | シークレット値混入、内部IP/エンドポイント露出、DB接続情報、APIキー漏洩チェック | セキュリティチェックリスト全項目PASS |
| **修正反映** | D-0.5 | CEO / Planning | QA・セキュリティ指摘事項の修正、最終文面確定 | 全指摘クローズ、修正済みマーク |
| **OGP/サムネイル反映** | D-0.5 | Design（星街） | サムネイルテンプレートにタイトル差し替え、OGP画像最終版納品 | 画像ファイル共有済み |
| **公開** | D-0 | Operations（白上） | noteへの投稿、OGP設定、SNSシェア投稿、管理ボードステータス更新 | note上で記事が公開済み、SNS告知済み |
| **効果測定** | D+1 | Operations（白上） | PV・スキ数・流入元の初動データ取得、管理ボードに記録 | 初動KPIが管理ボードに記載済み |

### タイムライン例（初回記事: 2026-03-05公開の場合）

```
3/2 (D-3)  : 構成・執筆開始
3/3 (D-1.5): ドラフト完成 → QA・セキュリティレビュー投入
3/4 (D-0.5): 修正反映・サムネイル最終版
3/5 (D-0)  : 公開・SNS告知
3/6 (D+1)  : 初動KPI記録
```

## 4. エスカレーションルール

| 状況 | 対応 | 判断タイミング |
|------|------|--------------|
| D-1.5までにドラフト未完成 | Operations → CEOへリマインド、翌日D-0.5まで延長可 | D-1.5当日 |
| QA/セキュリティで重大指摘 | 公開を1日延期、修正後に再レビュー | D-1レビュー完了時 |
| 2回連続で公開遅延 | 投稿頻度を一時的に4日おきへ緩和、根本原因を振り返り | 2回目遅延発生時 |
| 執筆者の体調不良等 | バッファ記事（ストック）から公開、次回以降で補填 | 可能な限り早期 |

## 5. 公開作業チェックリスト（Operations担当）

公開日（D-0）にOperationsが実施する作業:

- [ ] noteへの記事投稿（本文コピー、フォーマット確認）
- [ ] サムネイル画像のアップロード・設定
- [ ] OGP設定の確認（タイトル、説明文、画像）
- [ ] ハッシュタグの設定（#個人開発 #アプリ開発 #マネタイズ 等）
- [ ] 有料/無料設定の確認
- [ ] プレビューで最終表示確認
- [ ] 公開ボタン押下
- [ ] SNS告知投稿（poker_sns公式アカウント）
- [ ] 管理ボードのステータスを「公開済み」へ更新
- [ ] 公開URLを管理ボードへ記録

公開翌日（D+1）:
- [ ] PV数を管理ボードへ記録
- [ ] スキ数を管理ボードへ記録
- [ ] 流入元データの確認
- [ ] コメントがあれば返信対応

## 7. バッファ記事ストック運用

安定運用のため、常時1〜2本のバッファ記事をストックしておく。

- ストック対象: 時事性の低い汎用テーマ（マインドセット系、ツール紹介系）
- ストック管理: 管理ボードにステータス「ストック」として登録
- 使用条件: 執筆遅延時、体調不良時に代替公開
- 補填ルール: ストック使用後、次の通常サイクル内で新規ストック1本を補充
