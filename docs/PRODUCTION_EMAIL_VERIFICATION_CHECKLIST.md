# 本番環境：メール認証まわりチェックリスト

本番（prod）でメール認証・認証リンク・「コンテンツがブロックされました」が問題ないか確認するためのチェック項目です。

---

## 1. 本番デプロイ前の設定確認

### 1.1 バックエンド（Railway 本番サービス）

| 変数 | 本番で必須 | 確認内容 |
|------|------------|----------|
| `RESEND_API_KEY` | ✅ | Resend の API キーが設定されていること |
| `SMTP_FROM` | ✅ | **本番では Resend で認証済みドメインのアドレス**（例: `noreply@yourdomain.com`）。`onboarding@resend.dev` は届け先がテスト用アドレスに限定されるため本番不向き |
| `FRONTEND_URL` | ✅ | **本番フロントの URL**（認証リンクのベース）。例: `https://poker-sns.vercel.app`（末尾スラッシュなし） |
| `API_URL` | ✅ | 本番バックエンド URL（例: `https://xxx.up.railway.app`） |
| `CORS_ORIGINS` | ✅ | **本番フロントのオリジンのみ**（例: `https://poker-sns.vercel.app`）。dev 用 URL は含めない |

- Resend で本番ドメインを **Domains** に追加し、DNS 認証を完了しておく。
- 認証後、`SMTP_FROM` をそのドメインのアドレス（例: `noreply@yourdomain.com`）に設定する。

### 1.2 フロント（Vercel Production）

| 変数 | 確認内容 |
|------|----------|
| `NEXT_PUBLIC_API_URL` | 本番バックエンド URL（例: `https://xxx.up.railway.app`） |
| `NEXT_PUBLIC_SITE_URL` | 本番フロント URL（OGP・リンク用） |

- 環境は **Production** に設定されていること。

---

## 2. 本番デプロイ後の動作確認

### 2.1 メールが届くか

1. 本番フロントで **新規登録**（未使用のメールアドレスで）。
2. 数分以内に **認証メールが届く**ことを確認。
3. 届かない場合: Railway の本番サービス **Deployments → Logs** で `Verification email send failed` や Resend エラーが出ていないか確認。

### 2.2 認証リンクを開いて成功画面になるか

1. 届いたメールの **「メールアドレスの確認」リンク** をクリック。
2. **メールクライアントのプレビューで「このコンテンツはブロックされました」と出る場合**  
   → リンクを **右クリック → 新しいタブで開く** または **URL をコピーしてブラウザのアドレスバーに貼って開く**。
3. ブラウザで **認証完了ページ** が開き、**「メールアドレスが確認されました。」** と表示されることを確認。
4. **「ホームに戻る」** を押すとトップに戻り、画面上部の「メール認証してください」バナーが消え、**投稿できる**ことを確認。

### 2.3 エラーにならないか（修正済みの挙動）

- 認証に成功しているのに **「確認トークンが無効または期限切れです」** と表示される場合は不具合（dev で修正済み。本番も同じコードがデプロイされていれば発生しない想定）。
- 本番でも同じ症状が出る場合は、`frontend/src/app/verify-email/page.tsx` の「同一トークンで1回だけリクエスト」の修正が main にマージ・デプロイされているか確認。

---

## 3. 「このコンテンツはブロックされました」について

- **メール内のリンクを「プレビュー」で開いたとき**、送信先サイトが iframe 埋め込みを禁止していると、メールクライアントや Resend のプレビュー機能でこのメッセージが出ます。
- **アプリ側の不具合ではありません。** ユーザーには「リンクを新しいタブで開く」「URL をブラウザに貼って開く」と案内すれば問題ありません。
- 本番でも同様の表示になる可能性はあるが、**ブラウザで直接開けば正常に認証完了**します。
