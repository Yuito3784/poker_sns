# note記事 構成テンプレート: AI×個人開発ノウハウ

**作成日**: 2026-03-02
**作成者**: Planning (常闇)
**用途**: 各記事の執筆時に本テンプレートをベースに構成を組み立てる

---

```

```

---

## 構成テンプレート (6ブロック構造)

### Block 1: フック (300〜500字)

**目的**: 最初の3秒で「続きを読みたい」と思わせる

**必須要素**:
- 具体的な数字を含む「結論ファースト」の1文
- 読者の課題・痛みへの共感
- 「この記事で何が分かるか」の明示

**テンプレート**:
```
[具体数字を含む衝撃的な1文]

[読者の「あるある」な課題・悩み]

この記事では、[CEOの経験ベースの解決策]を[具体的な形式]で公開します。
```

**例**:
> AI導入後、開発速度は確かに3倍になった。でも品質は半分になった。
>
> 「AIを使えば生産性爆上がり」という話はよく聞くけど、実際にプロダクション環境で
> 3ヶ月運用してみた結果、想像と違ったことがいくつもあった。
>
> この記事では、1人で開発・運用しているWebサービスでAIを導入して起きた
> リアルな変化を、数字と具体例付きで全て公開します。

---

### Block 2: 背景・前提 (500〜800字)

**目的**: 読者が自分の状況と照らし合わせられるようにする

**必須要素**:
- CEOのスキルセット/開発経験年数
- サービスの規模感 (具体数字)
- 記事テーマに取り組んだ動機

**テンプレート**:
```
## 前提: 自分のスペックとサービスの状況

- 開発経験: [年数]
- 使っている技術: [スタック]
- サービス規模: [ユーザー数/売上等]
- この記事の時点での状況: [具体的な状態]
```

---

### Block 3: 本題 (1,500〜2,500字) ← 記事の核

**目的**: ノウハウの具体的な内容を伝える

**必須要素**:
- 見出しごとに具体的な数字 or 事例
- スクリーンショット or コードスニペット (1〜3個)
- 「やってみた結果」の数値変化

**構成パターン**:

| パターン | 適するテーマ | 構造 |
|---------|-------------|------|
| **時系列型** | 実録/体験談系 | Day1→Day30→Day90の変化 |
| **リスト型** | ○つのこと系 | 項目1→項目2→...→項目N |
| **比較型** | Before/After系 | 導入前→導入後 (数値比較表) |
| **ステップ型** | ガイド/全工程系 | Step1→Step2→...→完成 |

---

### Block 4: 失敗・落とし穴 (500〜800字)

**目的**: リアリティと信頼性を高める。成功談だけでは嘘くさくなる

**必須要素**:
- 実際にやらかした失敗 (1〜2個)
- その失敗で失った時間/コスト
- どうリカバリーしたか

**テンプレート**:
```
## ただし、こんな失敗もした

[失敗1の具体的なエピソード]
→ 結果: [失った時間/コスト]
→ 教訓: [1文で]

[失敗2の具体的なエピソード]
→ 結果: [失った時間/コスト]
→ 教訓: [1文で]
```

---

### Block 5: まとめ・再現ポイント (300〜500字)

**目的**: 読者が行動に移せるようにする

**必須要素**:
- この記事の要点を3行でまとめ
- 「明日からできること」を1つ提示
- 次回記事の予告 (連載感を出す)

---

### Block 6: CTA (100〜200字)

**目的**: poker_snsへの自然な導線

**パターンA (無料記事)**:
```
---
この記事で紹介した仕組みを実際に使っているサービス:
[poker_snsリンク (UTM付き)]

次回は「[次回テーマ]」について書きます。
noteのフォローで更新通知が届きます。
```

**パターンB (有料記事)**:
```
---
ここから先は、[具体的に何が書いてあるか]を公開しています。
- [有料パートの内容1]
- [有料パートの内容2]
- [有料パートの内容3]

[価格ボタン]
```

## 文字数配分ガイド (4,000字記事の場合)

| ブロック | 文字数 | 割合 |
|---------|--------|------|
| Block 1: フック | 400字 | 10% |
| Block 2: 背景 | 600字 | 15% |
| Block 3: 本題 | 1,800字 | 45% |
| Block 4: 失敗 | 600字 | 15% |
| Block 5: まとめ | 400字 | 10% |
| Block 6: CTA | 200字 | 5% |

---

## 画像・ビジュアル指針

| 種類 | 使用箇所 | 注意点 |
|------|---------|--------|
| OGP/サムネイル | 記事トップ | Design作成のテンプレートを使用 |
| スクリーンショット | Block 3 本題内 | 個人情報・APIキー等をマスク (QAチェック対象) |
| 比較表・グラフ | Block 3 本題内 | Before/After数値は必ず添える |
| コードスニペット | Block 3 本題内 | 10行以内に収める。長い場合はGist等で外部リンク |

## NGチェックリスト (執筆時確認)

- [ ] poker_snsの宣伝が記事の主目的になっていないか
- [ ] CEOの実体験に基づかない内容が含まれていないか
- [ ] 具体的な数字が1つも入っていないセクションはないか
- [ ] 読者が「で、自分は何をすればいい？」と思って終わらないか
- [ ] APIキー、内部URL、DBパスワード等が含まれていないか
