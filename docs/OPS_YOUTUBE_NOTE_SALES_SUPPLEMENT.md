## 1. YouTube展開 — 運用プロセス補足

### 1.1 アナリティクス自動収集モニタリング基盤

**収集対象KPI（週次）:**

| 指標 | データソース | 収集方法 | 頻度 |
|------|------------|---------|------|
| 視聴維持率 | YouTube Studio Analytics | YouTube Data API v3 + GAS | 週次（月曜AM） |
| CTR（クリック率） | YouTube Studio Analytics | 同上 | 週次 |
| poker_snsへの流入数 | GA4 (utm_source=youtube) | GA4 Data API + GAS | 週次 |
| 登録者増減 | YouTube Studio | YouTube Data API v3 | 週次 |
| インプレッション数 | YouTube Studio | YouTube Data API v3 | 週次 |

**自動収集パイプライン（推奨構成）:**

```
YouTube Data API v3 → Google Apps Script（定時トリガー）
  → Google Sheets（KPIマスターシート）
  → Slack通知（週次レポートサマリー）
```

- GASトリガー: 毎週月曜 09:00 JST に自動実行
- GA4のUTMパラメータ: `utm_source=youtube&utm_medium=video&utm_campaign={video_id}`
- 異常検知: 前週比 -30% 以上の指標を検知した場合、Slack即時通知

### 1.2 動画公開スケジュール管理フロー

既存の `OPS_VIDEO_CONTENT_SCHEDULE_KPI.md` を拡張し、以下のリードタイム定義を適用。

| 工程 | 担当 | 期日 (D = 公開日) | 所要時間 |
|------|------|------------------|---------|
| 企画・テーマ決定 | CEO + Planning | D-7 | 1日 |
| 撮影・収録 | CEO（撮影） | D-5 | 1日 |
| 編集 | 外注 or CEO | D-3 | 2日 |
| サムネイル制作 | Design | D-2 | 0.5日 |
| レビュー・承認 | QA + CEO | D-1 | 0.5日 |
| 公開設定・UTM付与 | Operations | D-0 | 0.5日 |

**遅延エスカレーション:**
- D-2にサムネイル未納 → Design担当へ自動リマインド + バッファテンプレ使用判断
- D-1にレビュー未完 → 1日延期 or CEO判断

### 1.3 初期運用の段階的スケジュール

| Phase | 期間 | 投稿頻度 | 目標 |
|-------|------|---------|------|
| Phase 1 (立ち上げ) | 1-2ヶ月目 | 週1本 | チャンネル開設、初期コンテンツ10本蓄積 |
| Phase 2 (安定化) | 3-4ヶ月目 | 週2本 | 登録者100人、poker_sns流入 週50人 |
| Phase 3 (拡大) | 5-6ヶ月目 | 週3-5本 | 収益化条件達成（登録者1,000 + 再生4,000h） |

## 2. note展開 — 運用プロセス補足

### 2.1 記事公開の定期スケジュール運用

既存の `NOTE_OPS_AUTOMATION_CHECKLIST.md` の3日おきサイクルを基盤とし、以下を補足。

**運用フロー（1記事あたり）:**

| Step | タイミング | 担当 | アクション |
|------|-----------|------|----------|
| 1. テーマ確定 | D-5 | Planning + CEO | シリーズ計画に基づくテーマ選定 |
| 2. 執筆 | D-3 ~ D-2 | CEO | 下書き作成 |
| 3. レビュー | D-1 | QA | 内容チェック + UTMリンク確認 |
| 4. 公開 | D-0 10:00 | Operations | note公開 + SNS告知 |
| 5. 初動KPI計測 | D+1 | Operations | PV・スキ数の初動確認 |

**バッファ運用:**
- 常時2本のバッファ記事ストックを維持
- 2記事連続遅延が発生した場合、頻度を4日おきに一時緩和

### 2.2 有料記事導入時の売上トラッキング

| 指標 | 取得方法 | 管理場所 |
|------|---------|---------|
| 有料記事売上 | noteクリエイターダッシュボード（手動） | Google Sheets KPIシート |
| 購入者数 | noteクリエイターダッシュボード | 同上 |
| 無料→有料転換率 | (購入者数 / 無料記事PV) × 100 | 同上 |
| poker_snsへの流入 | GA4 (utm_source=note) | GA4ダッシュボード |

**売上レポーティング:**
- 月次で売上レポートをCEOへ提出
- 有料記事の価格帯別パフォーマンス分析（100円 / 300円 / 500円の比較）
- 目標: 有料記事月間売上 3万円（Phase 2以降）

## 3. 営業活動 — 運用プロセス補足

### 3.1 営業パイプライン管理ツール選定

| ツール候補 | コスト | 特徴 | 推奨度 |
|-----------|-------|------|-------|
| Google Sheets + GAS | 無料 | 初期コスト0、カスタマイズ自由 | ★★★（Phase 1推奨） |
| HubSpot CRM (Free) | 無料 | CRM機能充実、メール追跡 | ★★★（Phase 2移行候補） |
| Notion | 月額$8~ | 柔軟だがCRM機能は弱い | ★★ |

**Phase 1推奨:** Google Sheets ベースの営業管理シート
→ 月間商談数 20件未満のうちはSheetsで十分。商談増加後にHubSpot移行。

### 3.2 営業活動KPI設計

| KPI | 目標値（月間） | 計測方法 |
|-----|-------------|---------|
| アプローチ数 | 30件/月 | 営業管理シートに記録 |
| 商談化率 | 10% (3件/月) | 返信 or ミーティング設定 |
| 成約率 | 30% (1件/月) | 契約・発注確定 |
| 成約単価 | 10万円~ | 案件ごとの売上記録 |
| パイプライン総額 | 50万円 | 商談中案件の合計額 |

**KPIレビューサイクル:**
- 週次: アプローチ数・返信率をSlack共有
- 月次: 全KPIの実績対比レポートをCEOへ提出
- 四半期: ターゲット業界・アプローチ手法の見直し

### 3.3 営業資料にサービス実績データを反映する自動化

poker_snsの実績データ（ユーザー数・投稿数等）を営業資料に反映するための仕組み。

**データ収集対象:**

| 指標 | 取得元 | 取得方法 |
|------|-------|---------|
| 登録ユーザー数 | PostgreSQL | `SELECT COUNT(*) FROM "User"` |
| アクティブユーザー数 (MAU) | PostgreSQL | `SELECT COUNT(DISTINCT "userId") FROM "Post" WHERE "createdAt" > NOW() - INTERVAL '30 days'` |
| 総投稿数 | PostgreSQL | `SELECT COUNT(*) FROM "Post"` |
| プレミアム会員数 | PostgreSQL / Stripe | `SELECT COUNT(*) FROM "User" WHERE "subscriptionStatus" = 'premium'` |

**自動化フロー（推奨）:**
```
月次バッチ（1日 AM）→ DB集計クエリ実行
  → Google Sheets（実績データシート）に書き込み
  → 営業資料テンプレ（Slides/PDF）に自動反映
```

- 手動の場合: 月初にOps担当が手動でDBクエリ実行 → Sheets更新
- 自動の場合: GASからバックエンドAPIのadminエンドポイント経由で取得

### 3.4 営業活動スケジュール管理

| 工程 | 頻度 | 担当 | 詳細 |
|------|------|------|------|
| ターゲットリスト更新 | 月次 | Operations + CEO | 新規アプローチ先30件リストアップ |

## 5. 運用リスクと対策

| リスク | 影響度 | 対策 |
|-------|-------|------|
| YouTube動画制作の属人化（CEO依存） | 高 | Phase 2以降で外注編集者を確保、テンプレート運用で再現性確保 |
| note記事の投稿遅延 | 中 | バッファ記事2本常備、自動リマインドで早期検知 |
| 営業活動の記録漏れ | 中 | 週次KPIレビューで漏れチェック、入力簡素化（テンプレ化） |
| 3チャネル同時運用の負荷過多 | 高 | Phase 1は段階的に立ち上げ（YouTube週1→note3日おき→営業日次） |
| アナリティクスAPI制限・変更 | 低 | GAS実行ログ監視、月次でAPI仕様変更チェック |
