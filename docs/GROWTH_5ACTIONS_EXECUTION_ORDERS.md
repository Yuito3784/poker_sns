## PART B: 開発チーム実装指示（技術仕様は KPI Matrix 参照）

### B-1. Week 1: インフルエンサー招待 基盤整備

**Dev (兎田) 担当**:
- `AffiliatePartner.tier` フィールド追加 (`STANDARD | INFLUENCER`)
- `POST /affiliates/influencer-apply` エンドポイント
- インフルエンサーティア: 報酬率50%、専用バッジ

**セキュリティ要件** (DevSecOps承認済み):
- `@Throttle({ default: { limit: 5, ttl: 60000 } })` on apply endpoint
- class-validator による入力バリデーション必須

### B-2. Week 2: 7日間無料トライアル

**Dev (兎田) 担当**:
- `User.trialUsed` フィールド追加
- `POST /subscriptions/start-trial` → Stripe `trial_period_days: 7`
- `customer.subscription.trial_will_end` Webhook ハンドリング
- `/pricing` ページCTA

**セキュリティ要件**:
- `@Throttle({ default: { limit: 3, ttl: 86400000 } })` — 3回/日
- trialUsed フラグで重複利用防止
- Stripe署名検証は既存基盤流用

### B-3. Week 3: OGP動的生成 + SNSバイラル

**Dev (兎田) + Design (百鬼) 担当**:
- 全ページ `generateMetadata()` 実装
- OG画像テンプレート（1200×630px、ダークテーマ準拠）
- シェアボタン拡充 + UTMパラメータ自動付与

**セキュリティ要件** (DevSecOps 獅白 指摘反映):
- OGPエンドポイント: `@Throttle({ default: { limit: 30, ttl: 60000 } })` — 30req/min
- `Cache-Control: public, max-age=3600, s-maxage=86400` 必須
- 外部大量リクエストによるサーバー負荷対策として必須

### B-4. Week 4: リファラルプログラム

**Dev (兎田) 担当**:
- `ReferralCode` + `ReferralRedemption` モデル
- `referrals` モジュール新規作成
- Stripeクーポン連携（双方Premium1ヶ月無料）

**セキュリティ要件**:
- `@Throttle({ default: { limit: 5, ttl: 60000 } })`
- リファラルコード: UUID v4（推測不可能）
- class-validator バリデーション必須

## PART D: リスクと対策

| リスク | 影響度 | 対策 |
|--------|--------|------|
| インフルエンサーからの返信なし | 高 | ターゲット30名→50名に拡大、報酬条件の見直し |
| コミュニティからスパム扱い | 中 | 管理者への事前許可取得必須、価値提供型投稿 |
| トライアル悪用（複数アカウント） | 中 | trialUsed + IP/Email重複チェック |
| OGPキャッシュ不整合 | 低 | Cache-Control + 手動パージ手順整備 |
| Stripe Webhook遅延 | 低 | リトライ機構 + 手動確認フロー |
