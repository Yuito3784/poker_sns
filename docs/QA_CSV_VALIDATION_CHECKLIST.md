# QA/QC バリデーションチェックリスト — ターゲットアカウントCSV

**作成日:** 2026-03-08
**担当:** QA/QC 尾丸
**目的:** CSV出力時およびAPI取得後のデータ品質を保証するバリデーションルール定義

---

## 1. 既存CSV精査チェックリスト

### 1.1 アカウント実在性検証
- [ ] 全件の `@ユーザーID` がX上に実在すること（X API `GET /2/users/by/username/{username}` で HTTP 200）
- [ ] 凍結・削除済みアカウントが含まれないこと
- [ ] ユーザーIDの大文字小文字がX上の表記と一致すること

### 1.2 フォロワー数フィルタ（CEO要件）
- [ ] 全件のフォロワー数が1000人未満であること（`public_metrics.followers_count < 1000`）
- [ ] フォロワー数が0のアカウント（bot疑い）がないこと

### 1.3 プロフィール情報正確性
- [ ] `ユーザー名` がX上の表示名と一致すること
- [ ] `プロフィール概要` がX上のbioと整合すること（完全一致不要、事実関係の齟齬がないこと）
- [ ] 名前の漢字・読みが正確であること

### 1.4 重複検出
- [ ] `@ユーザーID` に重複がないこと（完全一致）
- [ ] 同一人物/団体が異なるIDで複数登録されていないこと（名寄せ検証）

### 1.5 カテゴリ正確性
- [ ] 各アカウントが適切なカテゴリに分類されていること
- [ ] ランブック定義のカテゴリ名と一致すること

## 2. API取得後CSVバリデーションルール

### 2.1 構造検証（自動化可能）

| ルールID | 検証内容 | 判定基準 | 重要度 |
|----------|---------|---------|--------|
| V-001 | カラム数 | 5カラム（`@ユーザーID`, `ユーザー名`, `プロフィール概要`, `カテゴリ`, `ステータス`） | CRITICAL |
| V-002 | エンコーディング | BOM付きUTF-8（先頭3バイト: `EF BB BF`） | HIGH |
| V-003 | @プレフィックス | 全IDが `@` で始まること | CRITICAL |
| V-004 | null/空文字 | 全カラムに空セルがないこと | CRITICAL |
| V-005 | ID重複 | `@ユーザーID` がユニークであること | CRITICAL |
| V-006 | ステータス値 | `未連絡`/`DM済`/`返信あり`/`登録済`/`見送り` のいずれか | HIGH |
| V-007 | 行数 | データ行が目標件数に達していること | MEDIUM |

### 2.2 データ品質検証（API照合必要）

| ルールID | 検証内容 | 判定基準 | 重要度 |
|----------|---------|---------|--------|
| V-101 | アカウント実在 | X API で実在確認済み（HTTP 200） | CRITICAL |
| V-102 | フォロワー数 | `followers_count < 1000` | CRITICAL |
| V-103 | フォロワー数下限 | `followers_count > 0`（bot排除） | MEDIUM |
| V-104 | bio取得 | `description` が空でないこと | HIGH |
| V-105 | アカウント活動 | 直近90日以内に投稿があること | MEDIUM |
| V-106 | 日本語 | プロフィールまたは投稿に日本語が含まれること | MEDIUM |

### 2.3 ビジネスロジック検証

| ルールID | 検証内容 | 判定基準 | 重要度 |
|----------|---------|---------|--------|
| V-201 | ポーカー関連性 | bio/投稿にポーカー関連キーワードが含まれること | HIGH |
| V-202 | カテゴリ整合性 | アカウント内容がカテゴリと矛盾しないこと | MEDIUM |
| V-203 | 名寄せ | 同一人物/団体の重複登録がないこと | HIGH |

## 4. エスカレーション閾値

| 状況 | 閾値 | アクション |
|------|------|----------|
| フォロワー1000未満フィルタ後の残存件数が少ない | 50件未満 | CEOに報告、検索キーワード拡大を検討 |
| アカウント実在確認の不合格率が高い | 20%以上 | データソース・収集方法の見直し |
| APIレートリミット到達 | 429応答 | 15分待機後リトライ、1日の上限を超えた場合は翌日継続 |
