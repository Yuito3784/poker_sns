## 1. YouTube展開 — 検証サブタスク

### 1.1 動画説明欄リンク・UTM検証

| # | チェック項目 | 基準 | 確認方法 |
|---|------------|------|---------|
| YT-L1 | poker_snsリンクが正しいURLである | `https://{domain}/lp?utm_source=youtube&utm_medium=video&utm_campaign={video_id}` | 説明欄テキスト目視 + クリック確認 |
| YT-L2 | UTM source が `youtube` である | パラメータ値一致 | GA4 リアルタイムレポートで流入確認 |
| YT-L3 | UTM medium が `video` または `shorts` | Shorts/通常動画で分離 | GA4 キャンペーンレポート |
| YT-L4 | UTM campaign が動画識別可能な値 | `{video_slug}` 形式 | GA4 キャンペーンレポート |
| YT-L5 | リンク先 `/lp` が200レスポンスを返す | HTTP 200 | curl / ブラウザ確認 |
| YT-L6 | カード/エンドスクリーンのリンク先が正常 | 404でない | YouTube Studio プレビュー |

### 1.2 OEmbed埋め込み表示チェックリスト

| # | チェック項目 | 基準 | 確認方法 |
|---|------------|------|---------|
| YT-E1 | YouTube iframe がレスポンシブ表示される | 幅100%、アスペクト比16:9維持 | ブラウザ3サイズ (375px/768px/1440px) |
| YT-E2 | CSPヘッダーで `youtube.com` が許可済み | `frame-src` に `*.youtube.com` 含む | レスポンスヘッダー確認 |
| YT-E3 | iframe 読み込みエラー時のフォールバック表示 | リンクテキスト表示 | CSP blocking シミュレート |
| YT-E4 | 動画非公開/削除時の表示 | エラーメッセージ or プレースホルダー | 無効URL埋め込みテスト |
| YT-E5 | モバイル端末でのタッチ再生 | タップで再生開始 | 実機 (iOS Safari / Android Chrome) |
| YT-E6 | Shorts URL の埋め込み対応 | `/shorts/{id}` 形式でも正常表示 | Shorts URLでの埋め込みテスト |

### 1.3 チャンネル初期設定検証

| # | チェック項目 | 基準 |
|---|------------|------|
| YT-C1 | チャンネル名がブランドガイドラインに準拠 | poker_sns公式名称 |
| YT-C2 | チャンネルアートがDesign仕様に一致 | ブランドカラー(#c9a84c×#0d1009) |
| YT-C3 | サムネイルテンプレート3パターンが用意済み | Designチーム納品物と照合 |
| YT-C4 | チャンネル説明欄にpoker_snsリンクあり | UTM付きリンク |
| YT-C5 | デフォルト動画説明テンプレート設定済み | UTM・SNSリンク含む |

### 1.4 コンテンツ品質チェック（動画公開前）

既存の `docs/QA_VIDEO_CONTENT_CHECKLIST.md` を継続使用。追加項目:

| # | チェック項目 | 基準 |
|---|------------|------|
| YT-Q1 | Shorts は60秒以内 | YouTube Shorts要件 |
| YT-Q2 | サムネイルにブランドロゴが含まれる | Design仕様準拠 |
| YT-Q3 | タイトルに主要キーワード含む | SEOチェック |
| YT-Q4 | ハッシュタグ3〜5個付与 | `#ポーカー` 等 |

## 6. 判定基準・エスカレーション

### 公開ブロッカー（即時対応）

- UTMリンクが404を返す
- CSPブロックでiframe表示不可
- 営業資料のユーザー数が実数と20%以上乖離
- 個人情報の漏洩リスク（スクリーンショット内PII等）

### 警告（公開可能・次回修正）

- サムネイルの微細なカラー差異
- 記事の文字数が基準範囲の±10%以内の超過
- モバイル表示の軽微な余白ズレ

### エスカレーションフロー

1. **ブロッカー検出** → 即時Slack通知 → 該当リーダーに修正依頼 → 再テスト
2. **警告検出** → QAレポートに記録 → 次回公開時に修正確認
3. **判断困難** → Planning (桃鈴) にエスカレーション → CEO判断
