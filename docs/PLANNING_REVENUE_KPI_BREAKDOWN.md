## 2. 週次KPI定義

### 2.1 North Star Metric

**MRR (月次経常収益)** = プレミアム課金者数 × ¥980

これを頂点に、以下のツリーでブレイクダウン。

```
MRR (¥1,000,000)
├── プレミアム課金 (¥300,000)
│   ├── 課金者数 (307人)
│   │   ├── 新規課金/週 (15-20人)
│   │   └── チャーン率 (<10%/月)
│   └── ARPU (¥980 → ¥1,100目標)
│       └── 上位プラン導入率 (30%目標)
├── アフィリエイト (¥500,000)
│   ├── クリック数/週 (40+)
│   ├── CVR (40%+)
│   └── パートナー契約数 (3社+)
├── 広告 (¥150,000)
│   ├── 月間imp (30,000+)
│   └── 直販枠契約数 (2枠)
└── note/外部 (¥50,000)
    ├── 記事PV/月 (2,000+)
    └── UTM経由登録/月 (30人+)
```

## 3. KPIモニタリング運用

### 3.1 データ取得・集計フロー

```
[毎日 00:00 JST]
  DB → DAU / 新規登録数 / アフィリクリック数
  Stripe API → 課金者数 / MRR / チャーン

[毎週月曜 09:00 JST]
  GA4 → セッション数 / /lp PV / UTM経由登録
  X Analytics → インプレッション / エンゲージメント
  パートナーDB → アフィリCV数 / 成果額
  ↓
  Ops売上ダッシュボードに自動反映
  ↓
  Slack #revenue-kpi に週次サマリ通知
```

### 3.2 週次レビュー会議アジェンダ

**開催**: 毎週月曜 10:00 JST (15分)
**参加**: Planning + Ops + Dev (必要に応じてDesign/QA)

| 議題 | 時間 | 内容 |
|------|------|------|
| KPI速報 | 3分 | 前週実績 vs 目標 (GREEN/YELLOW/RED) |
| チャネル別深掘り | 5分 | 目標未達チャネルの原因分析 |
| アクション決定 | 5分 | 次週の改善施策 (最大3つ) |
| ブロッカー共有 | 2分 | 他チーム依存の課題エスカレーション |

### 3.3 アラート基準

| 状態 | 条件 | アクション |
|------|------|----------|
| GREEN | 目標の80%以上達成 | 継続。次週目標を10%上方修正検討 |
| YELLOW | 目標の50-79%達成 | 原因分析 → 次週に改善施策1つ追加 |
| RED | 目標の50%未満 | 緊急レビュー。施策変更またはリソース再配分をCEOに提案 |

### 3.4 KPI未達時のエスカレーションフロー

```
RED状態が2週連続
    ↓
Planning → CEO に現状報告 + 3案提示
    ↓
CEO判断 (24時間以内)
    ↓
判断に基づきリソース再配分 or 目標修正
```
