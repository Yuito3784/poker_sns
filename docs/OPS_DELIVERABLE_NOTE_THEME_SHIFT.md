---

## 1. テーマシフト方針

### 1.1 CEO方針の整理

**現状の課題**: 計画中の記事テーマがポーカー戦略（GTO、オッズ計算等）に寄りすぎている
**シフト先**: AI活用・個人開発・CEOの経験則に基づくノウハウ共有

### 1.2 CEOの過去記事から抽出した成功パターン

| 要素 | パターン | 適用ルール |
|------|---------|----------|
| タイトル構造 | 【実録】【体験談】【もしも】+ 具体数値 | 毎回いずれかのフック型を使用 |
| 数値フック | 「月3万」「150万溶かした」「5記事で回収」「週11時間」 | タイトルに必ず1つ以上の数値を含める |
| ペルソナ共感 | 「フォロワー200人台で」「今フォロワー0なら」 | 読者の現在地を明示して自分ごと化 |
| 実績ベース | 「6名に教えて5名が成功」「AI導入初月に」 | 抽象論ではなく実体験・実データで語る |
| AI軸 | 「AI導入」「AI投稿」「AIマーケ」 | AIを手段として具体成果に結びつける |

### 1.3 新テーマカテゴリと配分目標

| カテゴリ | 月間配分 | 記事テーマ例 |
|---------|---------|------------|
| AI活用ノウハウ (AI-OPS) | 30% (3本) | AI導入効果、AI×作業効率化、AI投稿自動化 |
| AI × マネタイズ (AI-MONEY) | 20% (2本) | AIで月X万稼ぐ、AI×SNS収益化 |
| 個人開発経験則 (DEV-EXP) | 20% (2本) | MVP構築、技術選定、1人運用術 |
| 実録・体験談 (BIZ-REAL) | 20% (2本) | 失敗談、回収ストーリー、再起プラン |
| フォロワー・集客 (GROWTH) | 10% (1本) | フォロワー施策、導線設計、インプレ改善 |

## 4. CI環境ワークフロー検証（運用テスト設計）

DevSecOps側のCopilot APIモデル修正後、`docs/`配下へのMDファイル追加がCI/CDパイプラインを正常通過することを確認するための運用テスト。

### 4.1 検証項目チェックリスト

| # | 検証項目 | 期待結果 | ステータス |
|---|---------|---------|----------|
| 1 | `docs/`配下に新規MDファイルを追加してpush | CI workflowが起動する | ⬜ |
| 2 | Markdown Lintチェック通過 | Lint errorなし (設定されている場合) | ⬜ |
| 3 | Backend test ステージ通過 | docs変更のみでもPASS (テスト対象外) | ⬜ |
| 4 | Frontend build ステージ通過 | docs変更のみでもPASS (ビルド対象外) | ⬜ |
| 5 | Docker build ステージ (mainのみ) | docs変更がビルドを妨げない | ⬜ |
| 6 | PRマージフロー | docs/のMD追加PRが正常マージ可能 | ⬜ |

### 4.2 検証手順

```
1. feature branchを作成
   git checkout -b docs/test-ci-workflow

2. テスト用MDファイルを追加
   echo "# CI Test" > docs/_CI_TEST_TEMP.md

3. commit & push
   git add docs/_CI_TEST_TEMP.md
   git commit -m "test: verify CI workflow for docs MD additions"
   git push origin docs/test-ci-workflow

4. GitHub ActionsのCI実行結果を確認
   - 全ステージがPASSすることを確認
   - エラーがある場合はログを取得

5. テスト完了後にクリーンアップ
   git rm docs/_CI_TEST_TEMP.md
   git commit -m "chore: remove CI test file"

6. 結果を本チェックリストに記録
```

### 4.3 ファイル命名規則（docs配下）

| プレフィックス | 用途 | 例 |
|-------------|------|-----|
| `OPS_` | Operations成果物 | `OPS_DELIVERABLE_NOTE_THEME_SHIFT.md` |

| `QA_` | QAチェックリスト・テスト | `QA_DELIVERABLE_NOTE_ARTICLE_PIPELINE.md` |
