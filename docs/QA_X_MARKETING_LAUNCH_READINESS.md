## 2. OGP実装状況の棚卸し結果

### 2.1 対象3ページの現状

| ページ | og:title | og:desc | og:image | twitter:card | OG画像生成 | 総合判定 |
|--------|----------|---------|----------|-------------|-----------|---------|
| `/` トップ | OK | OK | opengraph-image.tsx (自動) | OK | Edge Runtime 1200x630 | **概ね良好** |
| `/post/[id]` | OK (動的) | OK (動的) | OK (動的+投稿画像) | OK | Edge Runtime 1200x630 | **良好** |
| `/lp` | OK | OK | 未明示 (フォールバック) | OK | なし (ルートに依存) | **要確認** |

### 2.2 検出された課題

| # | 重要度 | ページ | 課題 | 影響 |
|---|--------|--------|------|------|
| 1 | MEDIUM | `/lp` | og:image が metadata に明示指定されていない | ルートの opengraph-image.tsx がフォールバックする可能性があるが、LP専用画像がない |
| 2 | LOW | `/` | layout.tsx の openGraph に images 配列が未設定 | opengraph-image.tsx ファイルが存在するため Next.js が自動補完するが、明示的であるべき |
| 3 | INFO | `/post/[id]` | ISR 60秒キャッシュ | X Card Validator でのクロールタイミングとの整合性は問題なし |

### 2.3 良好な実装ポイント

- `/post/[id]` の動的OG画像生成は本格的に実装済み（著者名、投稿内容、統計情報を含むリッチ画像）
- Schema.org 構造化データが全ページに実装済み
- twitter:card = "summary_large_image" が全ページで統一
- metadataBase が環境変数 NEXT_PUBLIC_SITE_URL で設定済み

## 5. 推奨アクション

### Dev向け（修正推奨: MEDIUM）
1. `/lp` ページに LP専用の `opengraph-image.tsx` を追加、または metadata に og:image を明示指定
2. `/` の layout.tsx openGraph に images 配列を明示追加（必須ではないが推奨）

### Ops向け
1. Dev修正マージ後、ステージング環境へデプロイ
2. QAに検証開始の連絡

### QA（自チーム）次ステップ
1. デプロイ完了通知を受け次第、`QA_X_OGP_CARD_VERIFICATION_CHECKLIST.md` に沿って検証実行
2. 全3ページのスクリーンショットをエビデンスとして保存
3. 合否判定を報告し、PASSであればX投稿開始のGo判定

## 6. リスク評価

| リスク | 確率 | 影響度 | 緩和策 |
|--------|------|--------|--------|
| LP のOGP画像がX上で空白表示 | 中 | 中 | ルートのフォールバック動作をValidator で事前確認 |
| Xキャッシュにより修正前のOGPが表示される | 低 | 中 | Card Validator で強制再クロール |
| Edge Runtime OG画像のフォント/レンダリング崩れ | 低 | 高 | 本番環境での実地検証が必須 |

## 7. 結論

OGPメタタグの実装は **概ね良好** な状態にあり、特に `/post/[id]` の動的OG画像は高品質。
`/lp` の og:image 明示設定が唯一のMEDIUM課題だが、ルートの opengraph-image.tsx がフォールバックとして機能する可能性が高い。

**X投稿開始判定:** デプロイ後のCard Validator検証でPASS確認後、投稿開始可能。
