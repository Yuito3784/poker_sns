## 1. model_not_supported エラー解消計画

### 1.1 問題の特定

```
{"error":{"message":"The requested model is not supported.",
"code":"model_not_supported","param":"model",
"type":"invalid_request_error"}}
```

**原因**: Copilot API呼び出し時に、対応していないモデルIDが指定されている。
**影響範囲**: 該当タスクのみ。プロダクションコードには影響なし。

### 1.2 解決アクション

| # | アクション | 担当 | 状態 |
|---|-----------|------|------|
| E-1 | エラー発生時のタスクログから指定モデルIDを特定 | Development | 兎田が引き取り済 |
| E-2 | 対応済みモデルに差し替え (例: `claude-sonnet-4-6`) | Development | E-1完了後即時 |
| E-3 | 差し替え後の動作確認 | Development | E-2完了後 |

### 1.3 再発防止ルール

- API呼び出し前にモデルID対応表を確認する手順を追加
- エラー発生時は即座にCEOへ通知し、ブロック解除判断を仰ぐ
- 担当変更 or タスク内容修正の2択で判断し、最大30分以内に再�kind

## 4. Development (兎田) へのリクエスト仕様

### 4.1 モデルID差し替え対応

**要件**:
- エラーが発生したCopilot API呼び出し箇所を特定
- モデルIDを対応済みモデル (`claude-sonnet-4-6` 等) に変更
- 変更後、同一タスクを再実行して動作確認

**完了条件**: エラーが解消し、タスクが正常に完了すること

### 4.2 今後のAPI呼び出しガイドライン

- 利用可能なモデルIDの一覧をプロジェクト内に文書化
- モデル指定は定数/環境変数で管理し、ハードコードを避ける
- エラーハンドリングでモデル非対応時のフォールバックを検討
