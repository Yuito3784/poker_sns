## 必須合格基準 (MUST)

以下の全項目が Pass であることが CEO 報告の最低条件:

### 1. サーバー応答

| # | 基準 | 確認者 | 判定方法 |
|---|------|--------|---------|
| M-1 | Vercel URL が HTTP 200 を返す | QA/QC | `curl -s -o /dev/null -w "%{http_code}" {URL}` |
| M-2 | `/lp` が HTTP 200 を返す | QA/QC | 同上 |
| M-3 | ページ読み込みが 5 秒以内に完了する | QA/QC | Chrome DevTools Network タブ |

### 2. LP ページ表示

| # | 基準 | 確認者 | 判定方法 |
|---|------|--------|---------|
| M-4 | LP のメインビジュアル・CTAが表示される | Design | 目視 |
| M-5 | LP のテキストコンテンツが全て読める | Design | 目視 |
| M-6 | LP でクリティカルな JS エラーが出ない | QA/QC | Chrome Console |

### 3. ログイン画面表示

| # | 基準 | 確認者 | 判定方法 |
|---|------|--------|---------|
| M-7 | ログインフォームが表示される | QA/QC | 目視 |
| M-8 | フォーム入力フィールドが操作可能 | QA/QC | 手動入力テスト |

### 4. フィード画面表示

| # | 基準 | 確認者 | 判定方法 |
|---|------|--------|---------|
| M-9 | フィード画面のレイアウトが崩れない | Design | 目視 |
| M-10 | API未接続でもクラッシュ(白画面)にならない | QA/QC | 目視 + Console |

## ビジュアル QA 基準 (Design 宝鐘 担当)

| # | 基準 | 対象画面 | 判定方法 |
|---|------|---------|---------|
| V-1 | ダークテーマ背景色 `#0d1009` が適用されている | LP, Feed, Login | DevTools Computed Style |
| V-2 | ゴールド CTA ボタン `#c9a84c` の視認性 | LP, Login | 目視 |
| V-3 | モバイル幅 (375px) でレイアウト崩れなし | LP, Feed, Login | Chrome DevTools Responsive |
| V-4 | テキスト読みやすさ (コントラスト比 4.5:1 以上) | 全画面 | 目視 |

## 許容事項 (Known Limitations in Phase 1)

以下はPhase 1では不合格要因としない:

| # | 許容項目 | 理由 |
|---|---------|------|
| A-1 | API fetch エラー (`ERR_CONNECTION_REFUSED`, `NetworkError`) | バックエンド未デプロイのため |
| A-2 | フィードに投稿が表示されない | APIデータ取得不可のため |
| A-3 | ログイン・登録の実行が失敗する | API未接続のため |
| A-4 | OGP画像が空 or デフォルト | SITE_URL未設定の可能性 |
| A-5 | 通知・ブックマーク等の認証必須ページがエラー | API未接続 + 未ログインのため |

## 不合格時のエスカレーション

| 不合格レベル | 状態 | 対応 |
|-------------|------|------|
| Critical | ページが全く表示されない (500, Build Error) | Development (兎田) へ即時エスカレーション |
| High | LP/ログイン画面でクラッシュ or 白画面 | Development (兎田) へ修正依頼 |
| Medium | ビジュアル崩れ (配色・レイアウト) | Design (宝鐘) と協議、修正後再デプロイ |
| Low | 軽微な表示差異 | CEO報告後に対応可 |
